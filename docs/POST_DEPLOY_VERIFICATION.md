## Fixtures and execution boundary

Use new, clearly named acceptance tenants in the approved deployed environment; never replace a company's real active dataset. Tests that replace/delete data use only these disposable tenants. The existing pytest tests use an isolated in-process test application and must not be represented as live HTTP deployment tests.

The primary reusable fixture is `_frame()` in `backend/tests/api/test_full_analyst_journey.py`: 48 rows, 24 consecutive days beginning 2026-01-01, North/South regions, five columns and one missing note. Independently calculated expectations are North revenue **4,020**, South **2,472**, total revenue **6,492**, total cost **2,232**, profit **4,260**, mean revenue **135.25**, and mean cost **46.5**. Exercise CSV, XLSX and JSON in separate acceptance tenants. Other rows below name small purpose-built fixtures already present in tests.

All `/analysis` actions refer to the implemented Brief → Prepare → Explore → Investigate → Share → Monitor tabs. `POST /api/v1/analysis/run` saves evidence; `GET /api/v1/analysis/profile` and read/export routes must not create evidence. UI requests must use the real deployed frontend/API origins.
